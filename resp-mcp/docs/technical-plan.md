## 1\. Goal and non-goals

**Goal.** A local, auditable system that pulls public respiratory virus surveillance data from a small set of API-native sources, harmonizes it into one schema in DuckDB, attaches a transparent quality score and provenance to every value, and exposes it through an MCP server so Claude (or any MCP client) can answer cross-source questions such as "How do NSSP emergency department visit percentages compare with NHSN admissions for Texas over the last eight weeks?" with the source definitions and caveats attached.

**Non-goals for the pilot.**

- No scraping of view-only dashboards (Tableau, Power BI, ArcGIS embeds). Those are logged as outreach targets (Section 10).  
- No forecasting or modeling. The system serves observed data and its quality attributes.  
- No PHI. Every source is public aggregate data. Keys, tokens and terms of use are still tracked per source.  
- No multi-user hosting. DuckDB file plus stdio transport is the pilot; Streamable HTTP and Postgres are the documented upgrade path.

## 4\. Harmonized schema

One long table of current observations, one table of report history, and reference tables. Column names below are canonical; adapters map source names to these and never add columns without a decision record.

```sql
CREATE TABLE source (
  source_id        TEXT PRIMARY KEY,   -- 'delphi_v5' | 'cdc_socrata' | 'ny_socrata' | 'pophive'
  organization     TEXT NOT NULL,
  platform_name    TEXT NOT NULL,
  base_url         TEXT NOT NULL,
  access_method    TEXT NOT NULL,      -- 'api' | 'file'
  terms_url        TEXT,
  requires_key     BOOLEAN NOT NULL,
  inventory_id     TEXT                -- PH-### from the landscape inventory spreadsheet
);

CREATE TABLE measure (
  measure_id       TEXT PRIMARY KEY,
  pathogen         TEXT NOT NULL,
  concept          TEXT NOT NULL,
  unit             TEXT NOT NULL,      -- 'percent' | 'count' | 'rate_per_100k' | 'copies_per_ml_lin' | 'level'
  numerator_def    TEXT NOT NULL,      -- plain English, from source documentation
  denominator_def  TEXT,
  definition_url   TEXT NOT NULL
);

CREATE TABLE source_measure (
  source_id        TEXT NOT NULL REFERENCES source(source_id),
  measure_id       TEXT NOT NULL REFERENCES measure(measure_id),
  source_signal    TEXT NOT NULL,      -- e.g. 'nssp/pct_ed_visits_covid' or 'rdmq-nq56.percent_visits_covid'
  native_geo_type  TEXT NOT NULL,
  native_period    TEXT NOT NULL,      -- 'mmwr_week' | 'week_ending_sat' | 'day' | 'sample'
  aggregation_rule TEXT,               -- how sub-weekly data is rolled to MMWR week, or NULL
  suppression_rule TEXT NOT NULL,      -- from source documentation, or 'none documented'
  stated_cadence   TEXT,
  republishes      TEXT,               -- source_id this signal republishes, if known (e.g. delphi nssp -> cdc_socrata)
  PRIMARY KEY (source_id, measure_id)
);

CREATE TABLE geography (
  geo_id           TEXT PRIMARY KEY,   -- 'US'; 2-digit state FIPS; 5-digit county FIPS; 'hhs_1'..'hhs_10'; 'nwss_<site>'
  geo_type         TEXT NOT NULL,      -- 'nation' | 'hhs' | 'state' | 'county' | 'sewershed'
  name             TEXT NOT NULL,
  parent_geo_id    TEXT,
  population       BIGINT,
  population_source TEXT              -- e.g. 'Census Vintage 2024'; NULL until populated
);

CREATE TABLE period (
  period_id        TEXT PRIMARY KEY,   -- 'MMWR-YYYY-WW', e.g. 'MMWR-2026-43'
  mmwr_year        INTEGER NOT NULL,
  mmwr_week        INTEGER NOT NULL,
  week_start       DATE NOT NULL,      -- Sunday
  week_end         DATE NOT NULL       -- Saturday
);

CREATE TABLE ingest_run (
  ingest_run_id    TEXT PRIMARY KEY,
  source_id        TEXT NOT NULL REFERENCES source(source_id),
  started_at       TIMESTAMP NOT NULL,
  finished_at      TIMESTAMP,
  status           TEXT,               -- 'ok' | 'partial' | 'failed'
  rows_fetched     INTEGER,
  rows_loaded      INTEGER,
  request_log      TEXT                -- JSON list of {url, status, elapsed_ms}
);

-- Current value per key. One row per (source, measure, geo, period, stratifier); overwritten on each ingest.
CREATE TABLE observation (
  obs_id           TEXT PRIMARY KEY,   -- sha1 of source_id|measure_id|geo_id|period_id|stratifier
  source_id        TEXT NOT NULL REFERENCES source(source_id),
  measure_id       TEXT NOT NULL REFERENCES measure(measure_id),
  geo_id           TEXT NOT NULL REFERENCES geography(geo_id),
  period_id        TEXT NOT NULL REFERENCES period(period_id),
  stratifier       TEXT NOT NULL DEFAULT 'all',  -- 'all' or 'age:0-4', 'sex:F', ...
  value            DOUBLE,             -- NULL when suppressed or missing
  value_status     TEXT NOT NULL,      -- 'reported' | 'preliminary' | 'suppressed' | 'missing'
  report_date      DATE NOT NULL,      -- date the source published this version
  retrieved_at     TIMESTAMP NOT NULL,
  ingest_run_id    TEXT NOT NULL REFERENCES ingest_run(ingest_run_id),
  quality_score    DOUBLE,             -- 0..1, Section 6
  quality_flags    TEXT[]              -- machine-readable reasons
);

-- Every version ever seen. Appended, never updated.
CREATE TABLE revision (
  source_id        TEXT NOT NULL REFERENCES source(source_id),
  measure_id       TEXT NOT NULL REFERENCES measure(measure_id),
  geo_id           TEXT NOT NULL REFERENCES geography(geo_id),
  period_id        TEXT NOT NULL REFERENCES period(period_id),
  stratifier       TEXT NOT NULL DEFAULT 'all',
  report_date      DATE NOT NULL,
  value            DOUBLE,
  value_status     TEXT NOT NULL,
  retrieved_at     TIMESTAMP NOT NULL,
  ingest_run_id    TEXT NOT NULL REFERENCES ingest_run(ingest_run_id),
  PRIMARY KEY (source_id, measure_id, geo_id, period_id, stratifier, report_date)
);

-- Notices and caveats published by sources (feed interruptions, methodology changes).
CREATE TABLE source_notice (
  notice_id        TEXT PRIMARY KEY,
  source_id        TEXT NOT NULL REFERENCES source(source_id),
  measure_id       TEXT,               -- NULL when it applies to the whole source
  geo_id           TEXT,
  notice_date      DATE NOT NULL,
  text             TEXT NOT NULL,
  origin_url       TEXT NOT NULL,
  structured_flag  TEXT,               -- set by a human, or by the Phase 5 classifier (then classifier_* filled)
  classifier_model TEXT,
  classifier_prob  DOUBLE
);
```

Rules that follow from the schema:

- **Observation versus revision.** `observation` holds only the latest version of each key; `load.py` upserts it. `revision` receives every version. `query_measure` reads `observation`; `get_provenance` reads `revision`. "Row counts reconcile with raw files" (Phase 2\) means: every row in the raw file for the ingest maps to exactly one `revision` row, and `observation` has one row per distinct key.  
- **Time.** Everything is keyed to MMWR weeks (Sunday to Saturday), named `MMWR-YYYY-WW`, never ISO weeks. `mmwr_weeks.csv` is generated once by `scripts/gen_mmwr.py` using the standard MMWR rule (week 1 is the week containing January 4\) for 2015 through 2030 and committed. Whether each source's week-ending date is a Saturday is **to confirm** per source in Phase 1 by checking the day of week of returned dates; the single live NHSN and NSSP queries on 2026-10-31 returned a Saturday (2026-10-24). Sub-weekly data (NWSS sample level) is rolled up in the adapter and the rule is recorded in `source_measure.aggregation_rule`.  
- **Geography.** State names and abbreviations are converted to two-digit FIPS using `state_fips.csv`. Source-specific labels that are not states ("New York City" in NSSP, territories, "USA", Delphi's lowercase `geo_value` format) are mapped in `geo_aliases.csv`, one row per source and label. Phase 0 enumerates the distinct `geography`, `jurisdiction` and Delphi `geo_value` values for state-level data and records them in that file. Delphi's `hsa_nci`, `hrr` and `msa` are out of scope for the pilot. NWSS sewersheds get `nwss_<site>` ids with `parent_geo_id` of their state.  
- **Suppression and missing.** A suppressed value is a row with `value NULL` and `value_status 'suppressed'`, never a dropped row and never zero. The adapter uses each source's documented suppression rule; if none is documented, `suppression_rule` is `'none documented'` and the observation carries the flag `suppression_undocumented`.  
- **Revisions.** Delphi V5 `archive/` with `report_time_query` provides the full report history of a value; V5 has no `lag` parameter, so lag is computed as `report_date - week_end`. SODA sources have no history; each ingest run appends the current value with that day's `report_date`, so history accumulates from the day ingestion starts.

## 5\. Adapter contract and environment

Each adapter implements this protocol and nothing else:

```py
class Adapter(Protocol):
    source_id: str
    def fetch(self, measure_id: str, geo_type: str, start: date, end: date) -> RawResponse: ...
    def normalize(self, raw: RawResponse) -> pd.DataFrame: ...   # columns exactly as the observation table, minus quality_*
    def describe(self) -> SourceMeta: ...                         # populates source and source_measure
```

Requirements:

- `fetch` writes the untouched response to `data/raw/<source_id>/<YYYY-MM-DD>/<measure_id>_<geo_type>.json` before returning. Raw files are never modified.  
- `normalize` is a pure function of the raw file. Re-running it on a stored raw file must produce identical output (tested on fixtures).  
- Retries: exponential backoff on HTTP 429 and 5xx, maximum 5 attempts. If `DELPHI_API_KEY` is unset, the Delphi adapter enforces the anonymous limits client-side and logs a warning on every run.  
- Every request URL, status and elapsed time goes into `ingest_run.request_log`.  
- Backfill window: 52 MMWR weeks ending with the most recent complete week at first run, then incremental (last 8 weeks re-fetched each run to catch revisions).  
- Archive history for revision volatility: for Delphi, pull `archive/` for the trailing 26 weeks only, one request per signal and geo\_type, to stay inside limits.  
- No adapter computes derived values. Smoothing, rates and comparisons happen in Layer 2 or in a tool, with the formula recorded in `measure-definitions.md`.

Environment (`.env`, loaded with `python-dotenv`):

| Variable | Used by | Notes |
| :---- | :---- | :---- |
| `DELPHI_API_KEY` | S1 | sent as header `Authorization: Bearer <key>` |
| `SOCRATA_APP_TOKEN` | S2 to S7 | sent as header `X-App-Token`; one token works across Socrata domains |
| `RESPMCP_DB_PATH` | all | default `data/respmcp.duckdb` |

## 6\. Quality score and confidence measures

This section answers the question "can we attach a confidence measure to each data point," including whether Jev (TypeSafe AI) has a role.

### 6.1 What a confidence measure can honestly mean here

No external model can know whether a surveillance value is accurate. What can be measured from verifiable attributes of each observation is how much a user should trust it for a decision today. The pilot computes a transparent `quality_score` in \[0, 1\] from six components. Each component produces a score in \[0, 1\] by the rule in the table and a flag when it crosses the threshold, so the score can always be explained. Components that cannot be computed for a row (for example cross-source agreement when only one source carries the measure) are excluded from that row's mean and the flag `component_unavailable:<name>` is set.

| Component | Measured as | Component score | Flag when |
| :---- | :---- | :---- | :---- |
| Freshness | `days_stale = today - report_date`, compared with the stated cadence `c` in days | `max(0, 1 - max(0, days_stale - c) / (2c))` | score below 0.5 (`stale`) |
| Completeness | share `p` of expected geographies for that measure and period present in the source | `p` | `p < 0.9` (`incomplete`) |
| Provisional status | `value_status` is `preliminary`, or the source marks the period as provisional (NHSN preliminary dataset; NCHS provisional flagging **to confirm** from `r8kw-7aab` metadata in Phase 0\) | 1 if final, 0.5 if preliminary | preliminary (`provisional`) |
| Revision volatility | median absolute percent change between first and latest report for the same measure, geography and lag over the trailing 26 weeks, from `revision` | `max(0, 1 - median_pct_change / 0.25)` | median above 10 percent (`volatile`) |
| Cross-source agreement | absolute relative difference between independent sources carrying the same measure, geography and period | `max(0, 1 - diff / 0.30)` | diff above 15 percent, or opposite direction of weekly change (`sources_disagree`). Pairs where `source_measure.republishes` links one to the other are excluded from this component and instead feed the ingestion check in Section 9 |
| Coverage | source-reported coverage where published (NWSS site count per state; NSSP facility participation if published) | `min(1, coverage / documented_threshold)`; unavailable if not published | below threshold (`low_coverage`) |

`quality_score` is the unweighted mean of available component scores. Thresholds and the option to weight components are parameters in `quality.py` with their defaults documented; they are starting values to revisit after Phase 3a produces real revision data. The score is advisory. It never suppresses data; it travels with the value and every tool returns it with its flags.

Revision volatility is the one component that is a true empirical confidence measure: Delphi's archive route makes it possible to measure, for every signal, how much the first-reported value typically moves before it settles. For SODA sources this component is unavailable until enough ingest runs have accumulated, and the flag says so.

### 6.2 Jev: what it is and where it fits

Jev is a decision model from TypeSafe AI. According to the secondary sources listed in `docs/endpoint-verification.md` (a Zapier article, a developer guide, and the promptfoo provider documentation; TypeSafe's own documentation at `docs.typesafe.ai` was not opened and the facts below are **unverified** against it), Jev does not generate text. Given a text or JSON "state" and typed questions it returns calibrated probabilities: a yes/no probability, a probability-weighted position on a 2 to 10 level rubric with a `confidence` field describing how concentrated the probabilities are, or a probability per option in a list. It accepts text only, with a reported limit near 32k tokens of state, is priced per input token, and gives no rationale. Calibration is claimed at the population level, not per answer. The promptfoo page quotes TypeSafe that Jev 1.13 "is unreliable at arithmetic, counting, and date comparisons," that score values are not calibrated for interpolating between levels, and that data retention for non-enterprise accounts should be confirmed with TypeSafe.

Consequences for this system:

- **Jev is not the source of numeric confidence for data points.** Freshness, completeness, revision size and cross-source agreement are arithmetic and date comparisons, which are exactly what Jev is reported to be unreliable at, and they can be computed exactly. The deterministic score in 6.1 is more accurate and is auditable.  
- **Jev is a candidate classifier for text the pipeline cannot otherwise structure**, used only in shadow mode (its output is logged to `source_notice.structured_flag` with `classifier_model` and `classifier_prob`, and nothing in the pipeline reads it) until measured against human labels. The pilot tests one use: classifying source notices (for example the NSSP feed-interruption and NWSS vendor-transition notices seen on the CDC Respiratory Illnesses Data Channel page on 2026-10-31) into a fixed label set with a catch-all option. Two further uses, a comparability rubric for `compare_sources` and a routing question for borderline cross-source differences, are recorded in `docs/decisions/` as deferred until the first use is measured.  
- **Governance.** A government-facing product needs explainable scores. Jev gives no rationale, so any flag it sets is labeled as model-classified and stored with the pinned model version, the probabilities and the input state. The model version string to pin and TypeSafe's retention terms are **to confirm** from `docs.typesafe.ai` before Phase 5\. Only public source metadata text is ever sent. Phase 5 is optional; the system is complete without it.

## 7\. MCP server design

Package `mcp` v2 (`pip install "mcp[cli]"`). Note the v2 rename: `from mcp.server import MCPServer`, not `FastMCP`. Transport `stdio` for the pilot; `streamable-http` is one argument change in `run()`.

Tools (all read-only; every response includes `source_id`, `measure_id`, definition URL, `report_date`, `retrieved_at`, `quality_score`, `quality_flags`, and a `stale_warning` when the last successful `ingest_run` for the source is older than 8 days):

| Tool | Inputs | Returns | Rules |
| :---- | :---- | :---- | :---- |
| `list_sources` | none | sources with last successful ingest, measures carried, cadence |  |
| `describe_measure` | `measure_id` | definition, unit, numerator and denominator, each source's native signal, suppression rule, open notices | the tool description tells the client to call this before `compare_sources` |
| `query_measure` | `measure_id`, `geo_type`, `geo_ids` (optional list), `start_period`, `end_period`, `source_id` (optional), `stratifier` (default `all`), `offset` (default 0\) | up to 5,000 long-format rows, `total_rows`, `next_offset` or null, `notes` | reads `observation` only |
| `compare_sources` | `measure_id`, `geo_id`, `start_period`, `end_period` | aligned rows from every source carrying the measure, relative difference per period, and a `comparability` block: whether the sources are independent or one republishes the other, and any differences in `native_period`, `suppression_rule` or definition | refuses with a message if units differ |
| `get_provenance` | `source_id`, `measure_id`, `geo_id`, `period_id`, `stratifier` | raw file path, request URL, ingest run, full `revision` history |  |
| `data_freshness` | optional `source_id` | per source and measure: latest period, report date, days since last successful ingest, behind-cadence flag |  |

Resources:

- `respmcp://dictionary` : the generated data dictionary.  
- `respmcp://measures` : measure definitions with source mappings.  
- `respmcp://crosswalks/{name}` : `state_fips`, `mmwr_weeks`, `geo_aliases`.  
- `respmcp://notices` : current `source_notice` rows.

Behavior enforced in code, not left to the model: suppressed values are returned as `null` with `value_status`; comparisons across different units are refused; every numeric answer carries its definition URL; the server never makes network calls.

## 9\. Review and audit workflow

Every pull request gets a multi-agent review before merge. Claude Code runs separate reviewer agents, each with only the diff, the relevant section of this plan, and one dimension below. Reviewers report findings with file and line; the implementing agent fixes each or records an accepted exception in `docs/decisions/`.

| Dimension | Reviewer brief |
| :---- | :---- |
| Accuracy to instruction | Does the change do what the phase's "Done when" says, with the exact IDs, column names and tool signatures in this plan? |
| Fidelity to the codebase | Naming, module boundaries and the adapter protocol are unchanged; no new columns, measures or tools without a decision record |
| Operational issues | Rate limits respected; retries bounded; raw files written before parsing; ingestion idempotent; a 52-week state-level run completes on a laptop in under 10 minutes |
| Known pitfalls and user errors | MMWR week alignment; non-state labels (New York City, DC, territories); suppressed versus zero; Delphi V4 versus V5 parameter names; Socrata `$limit` default of 1,000 silently truncating; `observation` overwritten while `revision` appended |
| Methodological consistency | Measure definitions match the source documentation URL; no derived value without its formula; quality thresholds are parameters, not literals; republished sources never counted as independent agreement |
| Messiness | Dead code, duplicated SODA logic, commented-out blocks, hard-coded paths |
| Interpretability | A stranger can read any module and the generated data dictionary and understand the pipeline; comments and docs are plain English |
| Deployment robustness | Fresh clone plus `.env` reaches a working `respmcp serve` by following the README alone |

Automated checks on every PR: `ruff`, `mypy --strict` on `src/`, `pytest tests/unit`, and a schema drift check (`schema.sql` versus the live DuckDB file). Integration tests run with `RESPMCP_LIVE=1`.

Ingestion fidelity check (Phase 3a onward, run by `respmcp audit`): for every `source_measure` pair linked by `republishes`, compare values for the same key and report any difference; a non-zero difference means a processing step on one side (for example Delphi smoothing or rounding) and must be explained in `measure-definitions.md`.

The Phase 6 audit additionally reconciles, for one state and one pathogen, every value in the DuckDB file against the raw API response and against the number shown on the source's own dashboard on the audit date, and records any discrepancy with its explanation.

# resp-mcp build rules

You are building the system described in docs/technical-plan.md. Read it fully before any change.

Non-negotiable rules
- Use only the endpoints, dataset IDs, signal names, column names and measure IDs listed in the
  plan and docs/endpoint-verification.md. If something is marked unverified or to confirm, verify it
  by opening the source documentation and record the result in docs/endpoint-verification.md before
  using it. Never substitute an identifier from memory.
- Never invent a column, measure, geography code or date. If a mapping is missing, stop and write
  the question into docs/open-questions.md.
- Raw API responses are written to data/raw before parsing and are never modified.
- Suppressed values are null with value_status 'suppressed'. They are never dropped or zeroed.
- observation holds the latest version per key; revision holds every version. Never update revision.
- No derived number is stored without its formula recorded in docs/measure-definitions.md.
- Code is production quality for an external reviewer: typed, documented in plain English, no
  internal jargon, no clever abstractions. Prefer boring code.
- Every PR runs the multi-agent review in plan Section 9 before it is opened for merge.
- American English spelling throughout code, docs and comments. No em-dashes.

Working style
- One phase per PR. State the phase and its "Done when" criteria in the PR description and show
  evidence (test output, row counts, sample tool responses) that each criterion is met.
- docs/data-dictionary.md and docs/erd.md are generated by scripts/gen_docs.py; do not hand-edit.
- Record each design decision in docs/decisions/NNNN-title.md (context, decision, consequences).
- When a source behaves differently from the plan (schema change, outage, new dataset), do not work
  around it silently. Record it in docs/open-questions.md and surface it in the PR.
